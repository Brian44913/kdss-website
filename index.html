Core capabilities

Engineered for data that has to last

From encoding and on-disk layout to access and operations, every layer is built around three goals: fewer drives, zero data loss, and simple operations.

Erasure coding

Profiles from 5+2 to 29+3, selected automatically for your cluster size. 29+3 delivers 90.6% usable capacity, and shards of a stripe never share a node.

Learn more →

Raw-disk engine

Writes straight to block devices, bypassing the local file system — sequential appends with CRC checks end to end. Freed space is reused by exact size and safely compacted.

Learn more →

POSIX and S3

Mount the cluster like a local directory with the FUSE client, or point AWS CLI, boto3 and other existing tools at the S3-compatible gateway.

Self-healing operations

Four layers of drive health monitoring, automatic isolation and rebuild, and rolling upgrades without downtime. The console shows exactly how much you can still write.

Storage economics

Store 10 PB of data on less than half the drives

Three-way replication keeps three full copies. With 29+3 erasure coding, KDSS adds only about 10% parity overhead — and tolerates one more simultaneous failure.

Architecture

Metadata and data decoupled, every tier scales out

A group of Masters elects a leader through a MongoDB replica set and manages metadata. Storage nodes own their raw disks directly. Clients encode locally and write shards to different nodes in parallel.

Master cluster

Typically five nodes with automatic leader election and failover. Handles metadata, stripe allocation, scheduling of repair, rebalancing and garbage collection, and placement audits.

Storage nodes

Each node manages many raw disks and handles shard I/O, local rebuild and drive health monitoring. Can be co-located with Masters.

Access tier

The ksfs FUSE client and the S3 gateway. Writes are redirected to the leader automatically; every shard read is verified for identity and CRC.

Reliability and operations

Detect, isolate and repair — automatically

Detect early

SMART collection, kernel log scanning, a stuck-I/O watchdog and a sliding window of I/O errors surface failing drives before they cause trouble.

Isolate automatically

Faulty drives leave the read/write path without slowing the cluster, and return on their own once a transient fault clears.

Rebuild in place

Storage nodes fetch surviving shards and decode locally, repairing the most degraded stripes first; hundreds of thousands of stripes are queued in minutes.

Upgrade without downtime

Nodes enter maintenance mode and are replaced one at a time. Upgrades are transparent to applications — no maintenance window required.
