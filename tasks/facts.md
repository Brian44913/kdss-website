所有页面与白皮书只能使用这里的事实与数字。不得出现：集群名（kdss-1/2/3）、IP、主机名、客户/矿工号、内部故障细节、安全弱点、密钥与端口以外的部署细节。

## 定位
- KDSS：面向 PB 级数据的分布式存储系统，纠删码（Reed-Solomon）冗余 + 裸盘直写引擎，同时提供 POSIX 文件挂载（FUSE 客户端 ksfs）和 S3 兼容接口，内置 Web 管理控制台。
- 关键词：低成本（高得盘率、追加写延长 HDD 寿命）、高可靠（多盘同时故障不丢数据、全链路校验、自动修复）、易运维（滚动升级不停服、可视化、内置告警）。
- 版本号采用 CalVer（YY.MM.PATCH），当前版本 26.11.1。

## 生产规模（概数，只能这样写）
- 累计裸容量近 190 PB（英文 ~190 PB）。2026-11-01 用户定：口径含 kdss-u 与规划中的存储容量，页面上不写括号说明。
- 300+ 存储节点、1.1 万+ 块数据盘（英文 11,000+）——按 190 PB 同比例推算（16 TB 盘约 1.19 万块，14 TB 盘约 1.36 万块，取下限；每节点 36 盘约 576 TB，约 330 台）。
- 管理条带数超过 7 亿（英文 700M+）——按容量同比例推算（1.8 亿 × 190/48 ≈ 7.1 亿）。
- 单集群规模：36 节点 × 36 盘（14–16 TB 企业级 HDD），约 16 PB 裸容量（14 TB 盘口径；不要写成 36×36×16 TB）。

## 纠删码
- 自动选型档位：5+2、9+2、18+3、29+3（按集群节点数自动选，保守安全默认）。
- 手动高密度档位：19+3、21+3、22+3、31+3（3 校验）、31+2（2 校验，容错下降，谨慎使用）。
- 得盘率：5+2 71.4%；9+2 81.8%；18+3 85.7%；22+3 88.0%；29+3 90.6%；31+3 91.2%。
- 29+3：任意 3 个分片同时丢失（盘或节点）数据仍可读、可重建；最少 33 个节点。22+3 最少 26 节点；18+3 最少 22；9+2 最少 12；5+2 最少 8。
- 同一条带的分片绝不落在同一节点（写入、修复、均衡三条路径强制校验，并有后台全量放置审计持续巡检）。
- 一个 256 MB 数据块 = 一条条带；29+3 下每个分片约 8.8 MB。条带粒度大，元数据量小（MongoDB 只记条带级元数据）。
- 编解码基于 klauspost/reedsolomon（SIMD 加速）。

## 存储引擎（裸盘直写）
- 直接写块设备，绕过本地文件系统：顺序追加写，4 KB 对齐，磁头寻道少，HDD 寿命更长、故障率更低。
- 双超级块（主 + 备份，CRC 保护），盘自带身份（节点 ID / 盘 ID / 盘 UUID），换槽位、换盘符后启动自动识别纠正，接错盘拒绝启动。
- 本地索引 BadgerDB；每次读取都做 CRC32 校验，流式读取同样校验。
- 崩溃恢复：干净关机秒级启动；异常断电从写入前沿向前扫描补齐索引；压缩/整理中断可整盘重建索引。所有磁盘并行打开。
- fsync 策略可选：immediate（默认，每次写入落盘）/ batch（组提交）/ deferred（带 BBU 阵列卡等场景）。
- 空间复用：删除是软删除，经回收站与可配置的冻结期后，同尺寸的空洞可被新写入直接复用（精确尺寸匹配，避免碎片）；碎片整理把尾部数据搬入空洞后截断回收，全程崩溃安全、搬移后逐片回读校验、元数据零改动。
- 三级容量保护：集群整体达到拒写线（默认 99%）停止新写入但允许修复；单盘达到上限（默认 99.5%，可配到 99.8%）退出写入环只接修复；单盘剩余 < 4 GiB 完全只读。控制台实时显示"当前最大可写 / 保守可写"。

## 数据可靠性与自愈
- 磁盘健康四层：SMART 周期采集、内核日志快速扫描（去抖确认）、读写卡死看门狗（读 120 s / 写 300 s 判定）、I/O 错误滑动窗口自动隔离与自动恢复。
- 修复：存储节点侧本地重建（拉取存活分片、本地解码落盘，减少中转），按缺失分片数最劣先修，批量建任务（数十万条带分钟级入队），多 master 分布式领取。
- 原位修复：换盘后把数据写回新盘原位置。
- 读路径身份校验：每次读带条带 ID / 分片序号核对，防止错误路由读到别人的数据。
- 后台 CRC 巡检（可限速，默认 20 MB/s/节点，可调周期）。
- 回收站 + 两阶段 GC：误删可从回收站恢复；GC 有可配置的保留窗口；孤儿分片只读对账工具。
- 均衡：显式触发的跨节点均衡（按偏离均值阈值挑源、按条带空闲集挑最空目标、双重查重 + 版本 CAS），以及节点内盘间均衡。

## 访问接口
- FUSE 客户端 ksfs：POSIX 挂载，`df -h` 显示集群真实容量，fsync 持久化，读写缓冲、并发、限速可调；写入可并行做 EC 校验。
- S3 兼容网关（已核对代码）：Bucket 级 ListBuckets / CreateBucket / DeleteBucket / HeadBucket / ListObjects；对象级 PutObject / GetObject（含 Range）/ HeadObject / DeleteObject / CopyObject；分段上传 CreateMultipartUpload / UploadPart / CompleteMultipartUpload / AbortMultipartUpload / ListParts / ListMultipartUploads。不要写未列出的 API（如版本控制、生命周期、对象锁）。大对象流式读写（≤64 MB 缓冲，超过则分段流式，内存可控）；可直接用 AWS CLI、s3cmd、boto3、Go SDK。
- 生产中约 99% 的读写走 FUSE。

## 运维与可观测
- Web 控制台（Vue 3 + Element Plus）：集群/节点/磁盘视图、容量面板（含当前最大可写/保守可写、回收站）、Bucket 与访问密钥、文件浏览、告警规则与渠道、审计日志、用户管理。
- 多用户 RBAC：admin / storage_admin / readonly；JWT 登录、bcrypt 口令、登录限速与验证码、CSRF 防护。
- Prometheus 全量指标（kdss_* 命名空间），/metrics 支持 Bearer 令牌认证；随版本提供 62 条告警规则模板。
- 内置告警系统：P0/P1/P2 分级、去抖与提醒间隔、飞书（Lark）与邮件推送、告警历史；含可写节点不足、容量、磁盘故障、MongoDB 存活、许可证校验失败等内置规则。
- 滚动升级不停服：维护模式（cordon）→ 等在途写入清零 → 替换 → 验证 → 退出维护，逐台进行；同时离线节点数不超过校验分片数 − 1。
- Master 多副本（典型 5 台）+ MongoDB 副本集（多数派写入）选主，Leader 切换自动；客户端写请求自动重定向到 Leader。
- 可选 gRPC mTLS（默认内网部署可关闭）。
- 许可证：在线校验 + 集群静默告警。

## 架构组件与端口
- Master（gRPC :6700，指标 :6701）：元数据、选主、调度（修复/均衡/GC/审计）。
- Storage（gRPC :6800，指标 :6801）：裸盘读写、本地重建、健康监测。
- Web 控制台 :8081；S3 网关 :9000。
- MongoDB 副本集：inodes / dentries / stripes / nodes / buckets 等集合，zstd 压缩，多数派写。
- 写入数据流（FUSE）：客户端缓冲到 256 MB → 向 Master 申请条带 → 本地 EC 编码 → 并行写 32 个分片到 32 个不同节点 → 提交元数据。
- 读取数据流：向 Master 取条带位置 → 并行读分片（CRC 校验）→ 缺分片时实时解码重建。

## 推荐硬件（来自生产实践）
- 存储节点：36 × 16 TB 企业级 HDD（JBOD 直通），Xeon 20 核级 CPU，64 GB 内存，2 × 10 GbE 绑定（20 Gbps），系统盘 RAID1。
- Master 可与 Storage 混合部署在系统盘为 RAID1 的节点上；MongoDB 副本集放 SSD。
- 最小可用：8 节点（5+2）。
