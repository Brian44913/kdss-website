为海量数据的长期保存而做

KDSS 是一套面向 PB 级数据的纠删码分布式存储系统。我们只做一件事：让大规模数据以更低的成本、更高的可靠性长期保存下来。

产品理念

为什么做 KDSS

数据量以 PB 计、要保存很多年的时候，真正的难题不是"存得下"，而是两笔账：硬盘买多少，坏盘时会不会丢数据。

三副本简单可靠，但三分之二的硬盘都在存重复数据；容量越大，这笔成本越难接受。另一方面，规模上去以后坏盘是日常，修复速度、升级是否停服、还能写多少数据，都直接决定运维负担。

KDSS 用纠删码代替副本、用裸盘直写代替通用文件系统，再把发现、隔离、修复、升级做成系统自带的能力，让大容量集群长期平稳地运行。

01

省硬盘

29+3 纠删码得盘率 90.6%，三副本只有 33.3%。顺序追加写减少磁头寻道，HDD 寿命更长。

02

不丢数据

任意 3 个分片同时丢失仍可读、可重建；同一条带的分片绝不落在同一节点；每次读取都做 CRC 校验。

03

好维护

坏盘自动隔离与重建，滚动升级不停服；控制台直接给出"当前最大可写 / 保守可写"，扩容心里有数。

生产实践

在真实的大规模集群上长期运行

KDSS 的每一项能力都在多个生产集群上经过长期验证，下面是累计规模。

近 190PB累计裸容量
300+存储节点
1.1万+块数据盘
7亿+在管条带

单集群典型规模：36 节点 × 36 盘，约 16 PB 裸容量。生产中约 99% 的读写经由 FUSE 客户端完成。

技术栈

成熟、可审计的基础组件

核心服务用 Go 编写，依赖经过大规模验证的开源组件，部署简单，便于排查。

Go

Master、存储节点、FUSE 客户端与 S3 网关的实现语言。

gRPC + Protocol Buffers

组件间通信，可选 mTLS 加密。

MongoDB

副本集保存条带级元数据，多数派写入，并承担 Master 选主。

klauspost/reedsolomon

Reed-Solomon 编解码，SIMD 加速。

hanwen/go-fuse

FUSE 客户端 ksfs 的文件系统层，提供 POSIX 挂载。

BadgerDB

存储节点的本地分片索引。

Gin

Web 控制台与 HTTP 接口的服务框架。

Zap + Prometheus

结构化日志与 kdss_* 全量指标。

Vue 3 + Element Plus

Web 管理控制台前端。

版本演进

持续交付，按日历编号

KDSS 采用日历版本号（CalVer），格式为 年.月.修订号。例如 26.11.1 即 2026 年 11 月的发布，从版本号就能看出代码新旧。

近期的主要能力演进见时间线。每个版本都可以通过滚动升级逐台替换，不需要停机窗口。

  1. 2026 · 基础

    纠删码与裸盘引擎生产化

    Reed-Solomon 纠删码、裸盘顺序追加写、双超级块与盘身份、全链路 CRC 校验，FUSE 与 S3 双接口。

  2. 空间效率

    填洞复用与碎片整理

    删除后的空洞按精确尺寸被新写入复用；碎片整理搬移尾部数据后截断回收，崩溃安全、逐片回读校验。

  3. 修复

    原位修复

    换盘后把数据写回新盘原位置；读路径增加条带 ID 与分片序号核对。

  4. 可见性

    可写容量面板与放置审计

    控制台实时显示"当前最大可写 / 保守可写"；后台全量巡检分片放置，确保同一条带不落同一节点。

  5. 运维

    内置告警与安全加固

    P0/P1/P2 分级告警，飞书与邮件推送；许可证在线校验；/metrics 支持令牌认证。

  6. 当前版本

    26.11.1

    以上能力全部包含在当前版本中。
