部署流程概览

一个 KDSS 集群按以下五个阶段部署。前一阶段完成并验证后再进入下一阶段。

准备 MongoDB 副本集

元数据和 Master 选主都依赖 MongoDB 副本集，写入采用多数派确认。副本集成员部署在 SSD 上。

部署 Master

典型部署 5 台，可与 Storage 混合部署在系统盘为 RAID1 的节点上。各 Master 连接同一副本集，自动选出 Leader。默认端口 gRPC 6700、指标 6701。

格式化并启动 Storage

数据盘以 JBOD 直通方式交给 KDSS。格式化时在盘首写入主、备超级块与盘身份（节点 ID、盘 ID、盘 UUID），此后换槽位或盘符变化都能自动识别。

启动存储服务（默认端口 gRPC 6800、指标 6801）后，节点及其磁盘会出现在控制台中。

初始化管理员

打开 Web 控制台（默认端口 8081），创建管理员账号；按需添加 storage_admin、readonly 角色的用户，并配置告警渠道（飞书 / 邮件）。

挂载 ksfs 或配置 S3

文件类业务在应用主机上挂载 ksfs；对象类业务在控制台创建 Bucket 与访问密钥，通过 S3 网关（默认端口 9000）访问。

纠删码档位按集群节点数自动选择（5+2 / 9+2 / 18+3 / 29+3）。如需使用高密度档位，请在部署前与技术支持确认。

推荐硬件

以下配置来自生产实践。冗余由纠删码在节点之间提供，数据盘不需要组 RAID。

项目推荐配置
数据盘每节点 36 × 16 TB 企业级 HDD，JBOD 直通
CPUXeon 20 核级
内存64 GB
网络2 × 10 GbE 绑定（20 Gbps）
系统盘RAID1
Master典型 5 台，与 Storage 混合部署在系统盘为 RAID1 的节点上
MongoDB 副本集部署在 SSD 上

最小规模

最少 8 个节点，使用 EC 5+2。节点越多，可选的纠删码档位越高、得盘率越高，各档位的最少节点数见下方档位表。

容量规划

规划有效容量时，同时考虑纠删码开销和集群的可用水位：

有效容量 = 裸容量 × 得盘率 × 可用水位裸容量 = 节点数 × 每节点盘数 × 单盘容量；得盘率 = k ÷ (k + m)
  • 得盘率：k 为数据分片数，m 为校验分片数。例如 29+3 的得盘率为 29 ÷ 32 ≈ 90.6%。
  • 可用水位：集群达到拒写线（默认 99%）后停止新写入、只保留修复，规划时以 99% 为上限。
  • 已删除但仍在回收站中的数据继续占用空间，直到冻结期与保留窗口结束。

算例

节点 × 盘 × 单盘档位裸容量 (TB)有效容量 (TB)
8 × 36 × 16 TB5+24,608≈ 3,259
12 × 36 × 16 TB9+26,912≈ 5,599
22 × 36 × 16 TB18+312,672≈ 10,753
33 × 36 × 16 TB29+319,008≈ 17,054

以最后一行为例：19,008 TB × 29/32 × 99% ≈ 17,054 TB。

硬盘容量按厂商标称的十进制 TB 计算；操作系统和 df 通常以二进制单位（TiB）显示，数值约小 9%。控制台的"当前最大可写 / 保守可写"会综合拒写线、节点余量与放置约束，给出实时可写量。

容错指同一条带可同时丢失的分片数（盘或节点）。自动档位按节点数选择，均为保守安全默认；手动档位的最少节点数为分片总数 + 1。

31+2 只有 2 个校验分片，容错能力低于 3 校验档位，换盘延误会直接增加风险，请谨慎使用。

S3 兼容接口

S3 网关默认监听 9000 端口，兼容核心 S3 API；已验证客户端：AWS CLI、boto3、s3cmd（按本节示例配置）。请求使用 AWS SigV4 签名，客户端使用路径风格（path-style）访问，region 填 us-east-1。访问密钥在 Web 控制台的"Bucket 与访问密钥"中创建。下文示例中的 <gateway> 请替换为网关地址。

支持的 API

类别操作
BucketListBuckets、CreateBucket、DeleteBucket、HeadBucket、ListObjectsV2
对象PutObject、GetObject（含 Range）、HeadObject、DeleteObject、CopyObject
分段上传CreateMultipartUpload、UploadPart、CompleteMultipartUpload、AbortMultipartUpload、ListParts、ListMultipartUploads
  • 大对象流式读写：64 MB 以内整体缓冲，超过后分段流式处理，网关内存占用可控。
  • 如需使用上表以外的 S3 功能，请先与技术支持确认。

AWS CLI

# Configure access keys (created in the web console) / 配置访问密钥（在 Web 控制台创建）
aws configure set aws_access_key_id     <ACCESS_KEY>
aws configure set aws_secret_access_key <SECRET_KEY>
aws configure set region us-east-1
EP=http://<gateway>:9000

# Create and list buckets / 创建并列出 Bucket
aws --endpoint-url $EP s3 mb s3://my-bucket
aws --endpoint-url $EP s3 ls

# Upload and download; large files use multipart upload automatically
# 上传与下载；大文件自动走分段上传
aws --endpoint-url $EP s3 cp ./video.mp4 s3://my-bucket/media/video.mp4
aws --endpoint-url $EP s3 cp s3://my-bucket/media/video.mp4 ./video.mp4
aws --endpoint-url $EP s3 ls s3://my-bucket/media/

# Read the first 1 MiB only (Range) / 只读取前 1 MiB（范围读）
aws --endpoint-url $EP s3api get-object --bucket my-bucket \
    --key media/video.mp4 --range bytes=0-1048575 head.bin

# Delete an object / 删除对象
aws --endpoint-url $EP s3 rm s3://my-bucket/media/video.mp4

Python（boto3）

import boto3
from botocore.config import Config

s3 = boto3.client(
    "s3",
    endpoint_url="http://<gateway>:9000",
    aws_access_key_id="<ACCESS_KEY>",
    aws_secret_access_key="<SECRET_KEY>",
    region_name="us-east-1",
    config=Config(s3={"addressing_style": "path"}),
)

# Create a bucket and upload (multipart for large files) / 创建 Bucket 并上传（大文件自动分段）
s3.create_bucket(Bucket="my-bucket")
s3.upload_file("dataset.tar", "my-bucket", "raw/dataset.tar")

# List objects under a prefix / 按前缀列出对象
for obj in s3.list_objects_v2(Bucket="my-bucket", Prefix="raw/").get("Contents", []):
    print(obj["Key"], obj["Size"])

# Range read, server-side copy, delete / 范围读、服务端复制、删除
part = s3.get_object(Bucket="my-bucket", Key="raw/dataset.tar", Range="bytes=0-1023")["Body"].read()
s3.copy_object(Bucket="my-bucket", Key="raw/dataset-copy.tar",
               CopySource={"Bucket": "my-bucket", "Key": "raw/dataset.tar"})
s3.delete_object(Bucket="my-bucket", Key="raw/dataset-copy.tar")

ksfs 挂载要点

ksfs 是 KDSS 的 FUSE 客户端，把集群挂载成本地目录，应用不需要任何改动。生产环境中约 99% 的读写经由 ksfs 完成。

  • POSIX 语义：以标准文件接口访问，现有程序和脚本可直接使用。
  • 真实容量：df -h 显示的是集群的真实容量，而不是本机磁盘。
  • 持久化：应用调用 fsync 后数据即持久化。对需要确认落盘的数据，应在写完后调用 fsync。
  • 客户端编码：写入在客户端缓冲到 256 MB 后编码成分片并行写出；写入时可并行做 EC 校验。
# Check cluster capacity from the mount point / 在挂载点查看集群真实容量
df -h /mnt/kdss

可调参数

参数类别作用
读写缓冲决定客户端在内存中缓冲多少数据；写缓冲按 256 MB 数据块组织。内存紧张的主机可适当调小。
并发同时进行的分片读写数量。网络与 CPU 充裕时调大可提高吞吐。
限速限制单个客户端的读写带宽，避免挤占同一网络上的其他业务。

具体参数名与默认值以随版本发布的配置参考为准。

日常运维要点

KDSS 的大部分故障处理是自动完成的，运维的重点是：看懂告警、按节奏换盘、按流程升级。

滚动升级

  1. 节点进入维护模式（cordon），不再接收新写入；
  2. 等待在途写入清零；
  3. 替换程序并重启，验证节点恢复正常；
  4. 退出维护模式，再处理下一台（默认逐台进行）。
同时维护的节点数上限为"校验分片数 − 1"（29+3 下最多 2 台），升级全程业务不中断。

坏盘处置原则

  • 先隔离，再更换：I/O 错误滑动窗口会自动隔离故障盘，使其退出读写；临时性故障恢复后自动回归。
  • 修复自动进行：缺失分片由存储节点侧本地重建，按缺失分片数"最劣先修"。
  • 换盘写回原位：更换新盘后，原位修复把数据写回新盘的原位置。
  • 控制同时故障数：确保任何条带同时缺失的分片数始终小于校验分片数；多块盘待换时分批处理。

磁盘健康巡检

  • SMART 周期采集：关注重映射、待处理扇区等指标的变化趋势。
  • 内核日志扫描：快速发现 I/O 错误，并做去抖确认。
  • 读写卡死看门狗：读 120 秒、写 300 秒无响应即判定卡死。
  • 后台 CRC 巡检：可限速（默认 20 MB/s/节点），巡检周期可调。

告警分级

内置告警系统按 P0 / P1 / P2 分级，支持去抖与提醒间隔，通过飞书（Lark）与邮件推送并保留告警历史；同时随版本提供 63 条 Prometheus 告警规则模板。

级别建议响应
P0立即处理。例如可写节点不足、MongoDB 不可用等影响写入或元数据的情况。
P1当天处理。例如磁盘故障、容量接近拒写线。
P2纳入例行巡检，跟踪趋势。

具体规则的级别以控制台中的告警规则配置为准，可按需调整。

容量与数据保护

  • 日常以控制台的"当前最大可写 / 保守可写"为准安排写入，而不是只看剩余空间。
  • 误删的数据可从回收站恢复；垃圾回收有可配置的保留窗口。
